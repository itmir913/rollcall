# 출결관리 (rollcall)

담임 교사가 하루치 출결을 빠르게 입력하고, 나이스 입력 여부와 증빙 서류
제출 여부를 놓치지 않기 위한 로컬 설치형 프로그램.

Tauri + Rust + SQLite + Vue.js · 단일 사용자 · 오프라인 동작

---

## 기준선

> **마우스로 조작한다. 출결 한 건이 클릭 몇 번으로 끝나야 한다.**

HOME 격자에서 학생 행의 `출석 · 눌러서 기록 추가`를 누르면 그 행 아래에 편집기가
펼쳐진다.

```
행 클릭  →  코드 버튼(질병 결석/지각/조퇴/결과 …)  →  필요하면 교시 버튼  →  증상  →  저장
```

- 출결 코드와 교시는 **드롭다운이 아니라 버튼**이다. 후보가 정해져 있으므로
  펼쳐 두면 한 번 클릭으로 끝나고, 무엇이 골라졌는지 눈으로 보인다.
- 타이핑이 필요한 곳은 증상·사유 한 칸뿐이고, 과거에 쓴 단어가 후보 버튼으로 뜬다.
- 확인 대화상자는 없다.

**키보드 단축 입력은 배포 직전에 정한다.** 지금은 없다.

## 저장소 구조

```
frontend/    데스크톱(Tauri) Vue 앱
src-tauri/   Rust
web/         웹앱 — GitHub Pages
```

데스크톱 앱과 웹앱은 별개다. 웹앱은 결석 번호를 짧은 코드로 바꾸는 계산만 하며
서버도 DB도 쓰지 않는다. 학생 이름은 웹앱에 오지 않는다.

## 명령어

사용자가 실행하는 것은 **셋뿐**이다. 나머지는 전부 이 셋의 조립이다.
웹앱도 `web/`에서 같은 셋을 쓴다.

```bash
npm install     # 처음 한 번 (SheetJS는 vendor/의 tarball에서 설치된다)

npm run dev     # 앱 실행
npm run build   # 설치본 빌드
npm test        # Rust(cargo test) + 프론트엔드(vitest) 전체
```

IntelliJ에서는 `.idea/runConfigurations/`의 `dev` · `build` · `test` 구성이 같은 셋을
그대로 가리킨다. 이 세 파일만 git에 포함하고 나머지 `.idea`는 제외한다.

## CI · 배포

GitHub Actions로 돌린다.

| 워크플로 | 언제 | 하는 일 |
|---|---|---|
| `ci.yml` | 모든 브랜치 push · PR | `npm test` → `npm run build -- --no-bundle` |
| `release.yml` | 손으로 실행 (Actions 탭) | 버전 확인 → 테스트 → 빌드 → **초안** 릴리스 |
| `pages.yml` | `web/` 변경 시 push | 웹앱 빌드 → GitHub Pages 배포 |

- **윈도우 러너에서 돌린다.** 이 앱은 윈도우용이라 경로·파일 잠금처럼 윈도우에서만
  나는 문제를 같은 OS에서 잡아야 한다.
- CI의 빌드는 `--no-bundle`이다. NSIS 패키징만 건너뛰고 프런트엔드 컴파일과 릴리스
  모드 Rust 빌드는 그대로 한다 — **단위 테스트가 못 잡는 Vue 템플릿 오류**가 여기서 잡힌다.
- 배포 버전은 `src-tauri/tauri.conf.json`의 `version` **하나만** 본다. 태그 push로
  자동 배포하지 않는 이유는 태그와 그 값이 어긋난 채 나가는 사고를 막기 위해서다.
- 같은 버전의 릴리스가 이미 있으면 빌드 전에 멈춘다.
- 릴리스는 **초안**으로 만들어진다. 노트를 손보고 사람이 직접 공개한다.
- 산출물은 설치본과 포터블 둘 다이며 zip으로 올린다 — `.exe`를 그대로 올리면
  브라우저와 백신이 내려받기를 막는 경우가 있다.

### 버전 올리기

`src-tauri/tauri.conf.json`의 `version`을 올린다. 스키마를 고쳤다면 `SCHEMA_VERSION`도
함께 올려야 한다(CLAUDE.md의 DB SCHEMA RULES).

## 화면 흐름

```
Welcome  →  초기 설정  →  HOME
```

HOME이 일일 입력 격자다. 첫 실행에서만 앞의 두 화면을 지나간다.

시각 디자인은 아직 정하지 않았다. 화면은 `frontend/src/components/ui/`의 프리미티브와
`frontend/src/style.css`의 토큰만 쓰므로, 디자인을 정하면 그 두 곳만 고치면 된다.
기본 테마는 라이트이고 다크와 "시스템 따름"을 설정에서 고를 수 있다.

불리언 입력에는 체크박스를 쓰지 않는다. 전부 `UiToggle`(큰 토글 버튼)이다.
출결 코드는 `CodePicker`, 교시는 `SlotPicker`, 구간 편집은 `SpanEditor`가 담당한다.

## 설계 결정

전부 [CLAUDE.md](CLAUDE.md)에 규칙으로 적혀 있다. 요약하면:

| 결정 | 이유 |
|---|---|
| 슬롯을 펼치지 않는다 | 나이스 실데이터에서 그날 슬롯 수가 1·3·6·7교시로 제각각이었다. 단축수업·시험일 때문이다. 시간표로 펼치는 설계였다면 그 날들에서 전부 틀렸다. |
| 프로그램은 판정하지 않는다 | 미인정 우선 같은 규칙을 자동 적용하지 않는다. 교사가 입력한 것을 그대로 저장한다. |
| 코드는 데이터다 | 출결 구분·체크 항목·서류 규정을 하드코딩하지 않는다. 학교마다 다르고 나이스 규칙도 바뀐다. |
| 수정은 마감 후 추가다 | 코드를 UPDATE로 고치면 과거 기록의 뜻이 소급 변경된다. `valid_to`로 마감하고 새 행을 넣는다. |
| 구간과 사유는 별도 테이블 | 한 테이블이면 하루 2구간(3교시 결과 + 6교시 조퇴)에서 막힌다. |
| 명렬표는 파일로 받는다 | 붙여넣기는 탭인지 쉼표인지 확실치 않다. 열은 이름(`학년·반·번호·이름`)으로 찾고 위치로 찾지 않는다 — 순서가 다른 파일에서 번호 자리에 학년이 들어가도 숫자라 조용히 통과한다. |
| 재가져오기는 차분이다 | 사라진 번호를 지우면 그 학생의 출결이 FK CASCADE로 함께 사라진다. 전출은 `enrolled_to`를 채우는 것이다. |
| 공휴일 캘린더를 두지 않는다 | 목적은 규정을 정확히 모델링하는 것이 아니라 "이 학생 서류 아직 안 냈다"를 놓치지 않는 것이다. 마감일은 교사가 직접 고칠 수 있다. |

### School-Record-App에서 가져온 것

- `with_transaction` — 트랜잭션이 열린 채 세션에 남으면 이후 모든 쓰기가 그 트랜잭션에
  묶이고, 앱을 닫을 때 작업이 통째로 롤백된다. 조기 반환은 반드시 클로저 안에서 한다.
- 스키마 잠금(`schema_lock_tests.rs`) — 마이그레이션 없이 `schema.sql`만 고치는 것을 막는다.
- `*_impl` 추출 — `State<DbState>`를 받는 함수는 테스트에서 부를 수 없다.
- 제약 위반 메시지 한국어 번역 — 안 하면 영문 SQLite 원문이 교사에게 그대로 표시된다.
- Store가 에러를 다시 던지는 계약 — 삼키면 읽기 실패가 "데이터 없음"과 구분되지 않는다.
- 열 때마다 백업, 앱은 백업 파일을 스캔·삭제하지 않는다.

## 아직 없는 것

- **DB 암호화.** 건강정보는 민감정보다. SQLCipher로 DB 전체를 암호화하고 비밀번호를
  메모리에만 두는 설계까지 정해져 있으나 구현하지 않았다. 그때까지 데이터 파일은
  평문이므로 공유 폴더·클라우드 동기화 폴더에 두지 말 것.
- 나이스 엑셀 대조 검증기
- 교과/동아리 출결 · 다학교 지원 · 월별 통계 · 웹앱 핀 입력 · 학사일정 관리

스키마는 이들을 나중에 붙일 수 있도록 설계되어 있다.

## 미결

1. **나이스의 하루 2구간 표기.** 실물 사례가 없어 확인 불가. 저장은 이미 지원하므로
   대조 단계에서 경고로 띄우고 교사가 판단한다.
2. **의존성 자동 업데이트(dependabot).** 설정을 한 번 넣었다가 지금은 뺐다. 앱 뼈대가
   자리 잡은 뒤 다시 넣는다. 되살리려면 `git show e993c32:.github/dependabot.yml >
   .github/dependabot.yml`. 그때 밀린 것은 pinia 3→4, vite 6→8, `@vitejs/plugin-vue` 5→6
   같은 메이저 업그레이드다 — CI는 통과했지만 스토어 동작은 단위 테스트가 보지 않으므로
   실제로 실행해 확인해야 한다.
3. **첫 실행 온보딩.** 학년도 → 학급 → 명단 순서로만 만들어 두었다. 비밀번호 설정
   단계는 암호화 구현과 함께 들어간다.
