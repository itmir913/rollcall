# 출결관리 (rollcall)

담임 교사가 하루치 출결을 **키보드만으로** 입력하고, 나이스 입력 여부와 증빙 서류
제출 여부를 놓치지 않기 위한 로컬 설치형 프로그램.

Tauri + Rust + SQLite + Vue.js · 단일 사용자 · 오프라인 동작

---

## 기준선

> **학생 1명 출결 입력 = 키보드만으로 5초 이내. 마우스를 쓰지 않는다.**

빠른 입력 한 줄이 주 경로다.

```
2 q 몸살        →  2번, 질병결석, "몸살로 질병결석"
5 w 6 복통      →  5번, 질병조퇴 6교시부터, "복통으로 6교시부터 질병조퇴"
```

토큰 순서는 `[번호] [단축키] [교시…] [증상…]`으로 고정이고, 코드가 교시를 몇 개
요구하는지는 유형이 정한다(결석 0개, 조퇴·지각 1개, 결과 2개). 번호와 교시가 둘 다
숫자여도 자리로 구분되므로 파싱이 결정적이다.

Enter로 저장한다. 확인 대화상자도, 저장 버튼도 없다.

---

## 명령어

사용자가 실행하는 것은 **셋뿐**이다. 나머지는 전부 이 셋의 조립이다.

```bash
npm install     # 처음 한 번

npm run dev     # 앱 실행
npm run build   # 설치본 빌드
npm test        # Rust(cargo test) + 프론트엔드(vitest) 전체
```

IntelliJ에서는 `.idea/runConfigurations/`의 `dev` · `build` · `test` 구성이 같은 셋을
그대로 가리킨다. 이 세 파일만 git에 포함하고 나머지 `.idea`는 제외한다.

## 화면 흐름

```
Welcome  →  초기 설정  →  HOME
```

HOME이 일일 입력 격자다. 첫 실행에서만 앞의 두 화면을 지나간다.

시각 디자인은 아직 정하지 않았다. 화면은 `src/components/ui/`의 프리미티브와
`src/style.css`의 토큰만 쓰므로, 디자인을 정하면 그 두 곳만 고치면 된다.
기본 테마는 라이트이고 다크와 "시스템 따름"을 설정에서 고를 수 있다.

불리언 입력에는 체크박스를 쓰지 않는다. 전부 `UiToggle`(큰 토글 버튼)이다.

## 설계 결정

전부 [CLAUDE.md](CLAUDE.md)에 규칙으로 적혀 있다. 요약하면:

| 결정 | 이유 |
|---|---|
| 슬롯을 펼치지 않는다 | 나이스 실데이터에서 그날 슬롯 수가 1·3·6·7교시로 제각각이었다. 단축수업·시험일 때문이다. 시간표로 펼치는 설계였다면 그 날들에서 전부 틀렸다. |
| 프로그램은 판정하지 않는다 | 미인정 우선 같은 규칙을 자동 적용하지 않는다. 교사가 입력한 것을 그대로 저장한다. |
| 코드는 데이터다 | 출결 구분·체크 항목·서류 규정을 하드코딩하지 않는다. 학교마다 다르고 나이스 규칙도 바뀐다. |
| 수정은 마감 후 추가다 | 코드를 UPDATE로 고치면 과거 기록의 뜻이 소급 변경된다. `valid_to`로 마감하고 새 행을 넣는다. |
| 구간과 사유는 별도 테이블 | 한 테이블이면 하루 2구간(3교시 결과 + 6교시 조퇴)에서 막힌다. |
| 재가져오기는 차분이다 | 사라진 번호를 지우면 그 학생의 출결이 FK CASCADE로 함께 사라진다. 전출은 `enrolled_to`를 채우는 것이다. |
| 공휴일 캘린더를 두지 않는다 | 목적은 규정을 정확히 모델링하는 것이 아니라 "이 학생 서류 아직 안 냈다"를 놓치지 않는 것이다. 마감일은 교사가 직접 고칠 수 있다. |

### School-Record-App에서 가져온 것

- `with_transaction` — 트랜잭션이 열린 채 세션에 남으면 이후 모든 쓰기가 그 트랜잭션에
  묶이고, 앱을 닫을 때 작업이 통째로 롤백된다. 조기 반환은 반드시 클로저 안에서 한다.
- 스키마 잠금(`schema_lock_tests.rs`) — 마이그레이션 없이 `schema.sql`만 고치는 것을 막는다.
- `*_impl` 추출 — `State<DbState>`를 받는 함수는 테스트에서 부를 수 없다.
- 제약 위반 메시지 한국어 번역 — 안 하면 영문 SQLite 원문이 교사에게 그대로 표시된다.
- Store가 에러를 다시 던지는 계약 — 삼키면 읽기 실패가 "데이터 없음"과 구분되지 않는다.
- 열 때마다 백업, 앱은 백업 파일을 스캔·삭제하지 않는다.

## 아직 없는 것

- **DB 암호화.** 건강정보는 민감정보다. SQLCipher로 DB 전체를 암호화하고 비밀번호를
  메모리에만 두는 설계까지 정해져 있으나 구현하지 않았다. 그때까지 데이터 파일은
  평문이므로 공유 폴더·클라우드 동기화 폴더에 두지 말 것.
- 나이스 엑셀 대조 검증기
- 교과/동아리 출결 · 다학교 지원 · 월별 통계 · 웹앱 핀 입력 · 학사일정 관리

스키마는 이들을 나중에 붙일 수 있도록 설계되어 있다.

## 미결

1. **나이스의 하루 2구간 표기.** 실물 사례가 없어 확인 불가. 저장은 이미 지원하므로
   대조 단계에서 경고로 띄우고 교사가 판단한다.
2. **첫 실행 온보딩.** 학년도 → 학급 → 명단 순서로만 만들어 두었다. 비밀번호 설정
   단계는 암호화 구현과 함께 들어간다.
